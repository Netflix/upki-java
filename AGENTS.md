# upki-java

- Use Ja's module-source-path layout, with production in `src/com.netflix.security.upki` and tests in `src/com.netflix.security.upki.test`. Do not introduce a separate Maven or Gradle build.
- Build with Ja 0.26.16+ and JDK 25+. Production code must use Java 8 language features and public JDK APIs only. Ship one multi-release JAR: Java 8 base classes, `META-INF/versions/9/module-info.java` with `@release 8`, and `META-INF/MANIFEST.MF` declaring the multi-release layout and agent entrypoint. Do not add project-specific packaging workarounds or raise the library's minimum Java version to work around tooling defects.
- Tests run on the development JDK. Compatibility fixtures must compile for and execute on the target runtime. Run `ja test --all` whenever changing `UPKI_TEST_JAVA_HOME`; runtime selection is not part of the test-cache identity.
- Mirror JDK security packages under `com.netflix.security`: provider registration in `provider`, JSSE integration in `ssl`, and UPKI-specific APIs and machinery in `upki`. Only `com.netflix.security.upki` and `com.netflix.security.provider` are unconditionally exported. Keep parsers, cache backends, and delegate-routing helpers internal.
- Keep the public API focused on provider installation, immutable configuration, standalone checking with structured results, and dependency-free diagnostic snapshots. Use the README for user documentation and the wiki if more is needed; do not maintain an implementation diary in the repository.
- [UPKI](https://github.com/rustls/upki) is the reference implementation, and [C2SP upki-revocation v1.0.0](https://c2sp.org/upki-revocation@v1.0.0) is the format and lookup contract. Go's integration proposal informs policy, not unquestioned acceptance behavior. Investigate discrepancies rather than silently copying them.
- Use public certificate and PKIX APIs, not internal JDK DER classes. Preserve delegated certificate verification and wrapper failures. Never substitute peer ordering, DN/signature matching, or an independent path build for the delegate's authenticated issuer.
- Integration targets ordinary same-thread, unpinned PKIX validation through early, first-priority trust-manager and PKIX builder/validator registration. Accept the JVM-wide JCA selection effect and document limitations around cached objects, custom or pinned verifiers, off-thread validation, and session resumption. Do not promise universal interception.
- Keep delegate construction and invocation routing in `DelegateFactory`, `DelegatingService`, and `InvocationGuard`. Preserve explicit construction failures and bounded delayed-selection loops. Do not silently fall back to another provider or pin SUN/SunJSSE in production.
- Cache failure policy supports fail-open and fail-closed without masking normal verification failure or confirmed revocation while checking is enabled. Missing-index policy separately supports `IGNORE`, `WARN`, and `FAIL`. Do not silently fall back from a corrupt selected cache.
- Diagnostics are immutable, pull-based snapshots: no I/O, background work, counter reset, or third-party logging/metrics dependency. Counters describe assessments, not all TLS handshakes. The standalone checker reports raw evidence even when configured policy would reject it; its caller must enforce acceptance.
- No-argument provider construction, installation, and the agent capture security properties once. Same-name system properties do not override them. Explicit configuration and fixed defaults remain property-independent. There is no hot reconfiguration or startup cache probe.
- Installation reuses only an equivalent, intact first-priority instance and fails on conflicts instead of replacing or reordering registrations. Static JCA loading can skip an invalid provider; uncaught programmatic or agent installation errors provide startup failure.
- Keep `src/com.netflix.security.upki/META-INF/LICENSE` and `NOTICE` byte-identical to their repository-root copies. Retain the full Go BSD license at `src/com.netflix.security.upki/legal/go-upki-LICENSE` and attribution in adapted source, fixtures, and NOTICE. UPKI's permissive license does not relicense its MPL-covered dependencies.
- Jfmt 0.9.0 has a known assertion for mixed Java 8 multi-release and ordinary dependent modules. Do not relocate the module descriptor or change the supported source layout to work around it.
